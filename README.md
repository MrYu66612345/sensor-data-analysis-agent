# 实验数据自动分析智能体（Demo）

用大模型 API 把「读数据 → 统计与拟合 → 判断数据质量 → 生成分析报告」串成一条自动化流程，并且让模型参与控制流：由它判断异常点剔除是否合理，不合理就给出新的判定阈值，程序据此重算。

## 要解决的问题

传感器标定实验的原始数据里常混入个别异常点——某次读数受干扰、接触不良，或者设备在某段行程上本身不稳定。人工逐条比对费时，判断又高度依赖经验。

常见的自动化做法是套一条固定规则：残差超过 2σ 就剔除。这条规则在真实数据上并不可靠，至少有两层原因：

1. **判据的尺度本身可能被异常点污染。** σ 由全部残差算出，异常点会把它抬高，阈值随之被顶高，异常点反而藏了起来。本仓库的示例数据里，两个异常点的残差是 0.54 和 0.63，而 3σ 阈值是 0.70——按教科书用 3σ，一个都筛不出来。
2. **固定的 σ 倍数假设噪声接近高斯分布。** 真实传感器的噪声常常是厚尾的，"偏离 2σ"并不等于"测量出错"。

所以这个项目的做法是：把"该用多大阈值"交给模型判断，并让它看到判断所需的全部证据。

## 分工

- 数值计算、拟合、残差统计由本地代码完成，结果可复现、可追溯
- 模型负责需要判断力的部分：这次剔除是否合理、阈值该调大还是调小、这份数据最终能不能用于标定、下一步该补做哪些实验

模型不直接读原始数据下结论，它在确定的统计量之上做解释和决策，每一步都有依据。

## 流程

```
读 CSV
  ↓
① 用当前阈值 t 判定异常点（|残差| > t·σ）
  ↓
② 有异常点 → 剔除后重新拟合
  ↓
③ 把数据表、排序后的残差表、两组拟合结果一起交给大模型
  ↓
④ 模型判断：合理   → 采纳本轮，结束
             不合理 → 由它给出新阈值 → 回到 ①
  ↓
⑤ 输出 report.md（可读报告）与 result.json（结构化结果）
```

几个刻意的设计选择：

- **判的是残差的标准差，不是原始数据的标准差。** 实验数据本身带有趋势，用「均值 ± σ」判定会被趋势撑大尺度，真正的异常点反而漏判；必须先把趋势拟掉，再看残差的分布。
- **给模型看排序后的残差表**，而不是只给统计摘要。残差分布中间常常存在天然的分界，只有看到排序结果才能发现它。
- **每一轮都从全部原始数据重新判定，不做累积剔除。** 阈值放宽之后，上一轮被误删的点必须能回到数据里，否则"放宽阈值"这个动作就没有意义。
- **阈值有安全边界**：夹紧在 1.5–4.0 之间，并且至少保留 60% 的数据点；任何一次夹紧都会写进报告，不会静默发生。
- **不收敛也不崩溃**：模型返回无法解析、没有给出可用阈值、阈值重复（可能振荡）、或达到轮数上限时，采纳当前结果并在报告里标注"未收敛"。

## 运行

只依赖 Python 标准库，无需安装第三方包。

```bash
# 1. 不联网，确定性验证迭代循环（脚本化响应：第 1 轮要求放宽阈值，第 2 轮接受）
python3 agent_demo.py --mock

# 2. 接真实接口
cp .env.example .env      # 填入 DEEPSEEK_API_KEY
python3 agent_demo.py

# 3. 换自己的数据
python3 agent_demo.py --input data/your_data.csv \
                      --x-column 位移_mm --value-column 输出电压_V

# 4. 指定初始阈值与迭代上限
python3 agent_demo.py --threshold 3.0 --max-rounds 4
```

在 WSL 里 `127.0.0.1` 指向 WSL 自身而非 Windows 主机，若 shell 中设有指向本机代理的 `http_proxy`，调用会以 `Connection refused` 失败。国内可直连 DeepSeek 接口，必要时先 `unset http_proxy https_proxy all_proxy`。

## 两份示例数据

**`data/sample_sensor_data.csv`（15 行，含 2 个明显异常点）**。用来展示"该剔除就剔除"：首轮按 2σ 剔除第 7、12 行之后，R² 由 0.847 升到 0.99999，残差标准差从 0.2327 降到 0.0020，说明这两个点确实不属于同一条标定直线。

**`data/sample_sensor_data_heavytail.csv`（21 行，噪声厚尾、没有真正的异常点）**。用来展示固定阈值为什么会失效——正常点的残差都在 ±0.6σ 以内，另有 4 个点落在 2.1–2.3σ，两者之间留有空档：

| 阈值 | 剔除点数 | 剔除行号 |
| --- | --- | --- |
| 2.0σ | 4 | 6、9、14、18 |
| 2.5σ | 0 | — |
| 3.0σ | 0 | — |

固定 2σ 在这份数据上会把 4 个正常测量当成异常点删掉；放宽到 2.5σ 以上则一个都不删。这正是需要模型来判断、而不是套公式的场景。

## 已知限制

- 初始阈值仍要人工给定（默认 2.0σ），模型只负责在迭代中调整它
- 迭代上限固定为 3 轮，且要求阈值严格变化才继续，因此复杂数据上可能提前停止并标记未收敛
- 夹紧区间 1.5–4.0 与"至少保留 60%"是人为设定的经验边界，不是推导出来的
- 判定用的是点对直线的残差，只适用于线性关系；真实的非线性段会被当成异常点，需要先更换模型
- 拟合仍是最小二乘，异常点本身会把直线拉偏（masking），未实现稳健回归或迭代重加权
- 模型可能给出无意义的阈值，靠夹紧规则兜底；`result.json` 里完整记录了每一次调整，便于事后审查
