# 实验数据自动分析智能体（Demo）

用大模型 API 把「读数据 → 统计与拟合 → 数据质量判断 → 生成分析报告」串成一条自动化流程的演示项目。

## 要解决的问题

传感器标定实验的原始数据里常混入个别异常点——某次读数受干扰、接触不良，或者设备在某段行程上本身不稳定。人工逐条比对费时，判断又高度依赖经验。

这个项目把这一环节自动化，但**分工是刻意的**：

- 数值计算、拟合、异常点筛选由本地代码完成，结果可复现、可追溯
- 判断类的工作交给大模型：异常原因是否合理、这份数据最终能不能用于标定、下一步该补做哪些实验

原因是：把原始数据整份丢给模型让它直接下结论，结果无法验证；让模型在确定的统计量之上做解释和决策，每一步都有依据。

## 流程

1. 读取 CSV 实验数据
2. 用最小二乘拟合出趋势，计算 R² 与残差标准差
3. 按「残差超过 2σ」筛出可疑点
4. 剔除可疑点后重新拟合，得到修正后的标定参数
5. 把数据表与两组拟合结果一并交给大模型，要求返回结构化 JSON
6. 输出 `results/report.md`（可读报告）与 `results/result.json`（结构化结果）

第 3 步不能用「均值 ± σ」判定：实验数据本身带有趋势，标准差会被趋势撑大，真正的异常点反而漏判。必须先去掉趋势，再判定偏离。

## 运行

只依赖 Python 标准库，无需安装第三方包。

```bash
# 1. 不联网，先验证流程
python3 agent_demo.py --mock

# 2. 接真实接口
cp .env.example .env      # 填入 DEEPSEEK_API_KEY
python3 agent_demo.py

# 3. 换自己的数据
python3 agent_demo.py --input data/your_data.csv \
                      --x-column 位移_mm --value-column 输出电压_V
```

在 WSL 里 `127.0.0.1` 指向 WSL 自身而非 Windows 主机，若 shell 中设有指向本机代理的 `http_proxy`，调用会以 `Connection refused` 失败。国内可直连 DeepSeek 接口，必要时先 `unset http_proxy https_proxy all_proxy`。

## 示例输出

仓库自带 `data/sample_sensor_data.csv`，其中人为插入了 2 个异常点。

| | 剔除前（15 个点） | 剔除后（13 个点） |
| --- | --- | --- |
| 标定关系 | y = 0.2534 x - 0.0214 | y = 0.2705 x + 0.0107 |
| R² | 0.84701 | 0.99999 |
| 残差标准差 | 0.2327 | 0.0020 |

剔除两个点后 R² 由 0.847 升到 0.99999，残差标准差降到原来的 1%，说明异常判定有效，这两个点确实不属于同一条标定直线。

## 已知限制

- 异常判定用固定的 2σ 阈值，未使用稳健回归，阈值对样本量敏感
- 只处理单文件，未考虑批量与并发
- 未做交叉验证；剔除异常点后没有用独立数据检验标定关系的泛化能力
- 模型返回的 JSON 只做了解析容错，未做 schema 校验
